# copper-dsn

The file-format layer: a Specctra `.dsn` reader that builds a
`copper_board::Board`, writers for `.dsn`, `.ses` and `.rules`, a `.ses` and
`.rules` reader, and the KiCad board-JSON reader and writer. Use
`copper_dsn::prelude::*` to bring in every public type.

The crate sits directly on `copper-board` and `copper-geometry`. It builds boards
through `copper-board`'s public insert API and reads them back through
`get_traces`/`get_vias`/`get_connectable_items`/`items_in_board_order`; it
owns no board state of its own. `serde`/`serde_json` are used by the KiCad
module and the JSON formatter only. No `regex`, no `tracing`: reader
diagnostics go onto `ReadScopeParameter::warnings`.

## Entry points

| What you want | Call |
|---|---|
| read a `.dsn` into a board | `read_board(input, &DsnReadOptions) -> BoardReadResult` |
| only the header (layer count, unit, resolution, embedded router settings) | `read_metadata(input) -> BoardReadResult` |
| write a board as `.dsn` | `dsn_writer::write(&mut w, &board, &ct, …)` |
| write a routing session (`.ses`) | `ses_writer::write(&mut w, &board, &ct, …)` |
| apply a session to a board | `ses_reader::read(input, &mut board, …) -> SesImportSummary` |
| write / read a `.rules` file | `rules_writer::write`, `rules_reader::read`, `rules_reader::read_router_settings` |
| a KiCad board JSON | `kicad::read_board`, `kicad::import_session`, `kicad::write` |
| a `.kicad_pcb` file | `kicad::pcb::read_pcb(text, name, &defaults) -> Result<ImportedPcb, PcbError>` |

`BoardReadResult` is `Success { board, metadata, coordinate_transform, warnings }`,
`OutlineMissing` (the same, for a design with no outline), `Partial` (the
file ended inside an unclosed scope; the board built so far is returned with
that fact recorded), `ParseError` or `IoError`. `BoardMetadata` carries the
host CAD name and version, layer count, unit, resolution, snap angle, and the
`(autoroute_settings …)` block as a `DsnRouterSettings` when the file has one.

`CoordinateTransform` — the unit and resolution a file was read in — is
threaded explicitly: `BoardReadResult::Success` carries the one the reader
built, and every writer takes `ct: &CoordinateTransform`, because that is the
only transform that round-trips the file's coordinates unchanged.

## Layout

| Module | What it holds |
|---|---|
| `lexer/` | `DsnScanner`, a table-driven tokeniser (`tables.rs` is generated by `scripts/gen-lexer-tables.py`), and `Token { Open, Close, Kw, Str, Int, Float }` |
| `keyword.rs` | `Keyword` and `ScopeKeyword`, the token vocabulary |
| `parser/` | one module per scope family — `structure`, `library`, `part_library`, `placement`, `network`, `wiring`, `autoroute_settings`, `geometry`, `header`, `dsn_file` — plus `ReadScopeParameter`/`WriteScopeParameter`, the state threaded through a read or a write |
| `dsn_reader.rs`, `dsn_writer.rs`, `ses_reader.rs`, `ses_writer.rs`, `rules_reader.rs`, `rules_writer.rs` | the six file-level entry points |
| `kicad/` | `dto.rs` (the board-JSON document types, field names matching the wire format), `reader.rs`, `writer.rs` |
| `format/` | `IndentFileWriter`, `IdentifierType` (quoting rules for identifiers, with the DSN and SES reserved-word tables), `double` (fixed-width and shortest-round-trip number formatting), `json` (`to_gson_string_pretty`, the JSON layout shared with `copper-settings` and `copper-drc`) |
| `coordinate_transform.rs` | `CoordinateTransform` |

### Read lexemes and write literals are independent

Three things are kept separate and must not be conflated: the scanner's
lexeme → `Keyword` table, `Keyword::name()`, and the literal strings each
writer emits. A scope can be read under one spelling and written under
another (`(rect …)` is written where the keyword is named `rectangle`), so a
change to one table is not a change to the others.

### The KiCad board-JSON reader

`kicad::read_board` builds a board from a KiCad board JSON: units, layer
structure, clearance matrix, outline, net classes, nets, padstacks,
packages, components and pins, conduction areas, traces and vias. Things
worth knowing before touching it:

- **Nets are numbered in first-reference order.** Auto-registered nets get
  their numbers in the order the file first mentions them, so numbering is a
  pure function of the file.
- **A malformed board is refused at the DTO boundary.** A `null` where the
  board needs a name — a layer, a net class, a net, a component reference, a
  pad — or a `null` array element is refused by `KiCadBoardJson::validate`
  with a diagnostic naming the file, the section and the object.
- **A pad's padstack is keyed on its shapes and its drill, not on its
  generated name.** The name encodes neither the layer span nor the drill;
  `unique_padstack_name` keeps display names unique.
- **The clearance matrix it builds is asymmetric on purpose.** The reader
  writes one entry per class pair, and `ClearanceMatrix` readers ask for the
  `(a, b, layer)` triple they mean.

### Reading a `.kicad_pcb` file directly

`kicad::pcb::read_pcb` parses a `.kicad_pcb` file's S-expressions straight into a
`KiCadBoardJson`, returned as `ImportedPcb { board, warnings, embedded_net_classes }`; pass
the result's `board` to `kicad::read_board_json` to get a `copper_board::Board`.
`embedded_net_classes` is the number of `(net_class ...)` entries the file carried, so
callers can tell whether the board defines its own rules or needs a `.kicad_pro`.
`kicad::pcb::default_net_class` gives the net class values the reader falls back on when the
file has no `Default` net class.

- **Some constructs are refused outright.** Curved tracks, net ties, footprint zones, locked
  tracks, concave custom pads, zone keepouts that restrict tracks or vias, netless copper
  zones, locked/blind/micro vias, and through vias with no net all fail the read rather than
  being approximated.
- **Copper zones that carry a net are kept, not routed.** They come through with their fill
  cache removed and a warning attached: the reader works in tracks only, and expects KiCad to
  refill zones once the board comes back.
- **A curved board edge is approximated for routing, not discarded.** The outline is
  flattened to straight segments within 0.005 mm and a warning records it; the original
  curved outline is preserved wherever the board is written back out.

## Invariants

- **`normalize_all_traces` runs under a stop check.** Every `.dsn` read ends
  with trace normalisation, which can loop on pathological same-net ladders.
  `DsnReadOptions::normalize_time_limit` (default 60 s) bounds it; when it
  trips the reader records `"Wiring: normalization of traces failed"` as a
  warning and continues. `Duration::ZERO` is a deterministic opt-out. No
  fixture in the corpus comes near the limit, and the corpus test asserts it.
- **UTF-16 code-unit string order.** Several structures are keyed by name in
  UTF-16 code-unit order, which differs from Rust's code-point `str: Ord`
  above the BMP. Where the order is observable in the output, the writers
  use `utf16_cmp` (`parser/part_library.rs`), not the derived `Ord`.
- **Descending item iteration.** Every writer walks the board through
  `Board::get_items`/`items_in_board_order` — newest item first — and the
  output bytes depend on it.
- **The scanner buffer is sized to the input.** `DsnScanner::new` is
  infallible; there is no input-size ceiling.
- **Never edit a reference output by hand.** `tests/reference/<stem>/` is
  produced only by the generator scripts under `scripts/`.

## Tests

`cargo test -p copper-dsn` runs the unit tests plus the integration suites in
`tests/`: the lexer, the number formatters, `IdentifierType`, each scope
family (`structure_scope`, `library_scope`, `placement_scope`,
`network_scope`, `geometry_scopes`, `scopes`, `wiring`, `network`), the DSN
reader, the SES and rules round trips, the KiCad DTOs, reader, writer and
round trip, the JSON formatter (`gson_format`), and the two byte-parity
suites `parity_dsn` and `parity_ses`, which compare the writers' output
against the committed reference files in `tests/reference/` byte for byte.

The corpus test in `tests/dsn_reader.rs` reads every
`.dsn` in the fixture corpus and compares the `BoardReadResult` variant and
the complete warning list against a committed golden. It is `#[ignore]`d in
debug builds (~90 s) and runs unconditionally in release —
`cargo test -p copper-dsn --release`, or `--ignored` in debug. Its always-on
sibling checks that the golden still parses and still names every fixture.

### What needs the fixture corpus

The boards live in `tests/corpus` and the expected outputs in
`tests/reference/`; both travel with the repository. `parity_ses` re-cuts its
references under `COPPERROUTE_REGOLDEN=<label>`.

`tests/kicad_pcb_corpus.rs` runs `read_pcb` against a further set of real `.kicad_pcb`
boards that does not travel with the repository. It skips unless `COPPERROUTE_PCBENCH` names
the corpus root; run it with `COPPERROUTE_PCBENCH=<corpus root> cargo test -p copper-dsn
--test kicad_pcb_corpus -- --nocapture`.
