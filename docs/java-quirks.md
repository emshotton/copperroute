# Java quirks, bugs, and improvement candidates

This port is **behavioral**: it reproduces freerouting (Java, v2.3.0 baseline)
exactly, including its bugs, so that parity against the Java outputs is the
acceptance test. Every deliberate reproduction of a Java defect is recorded
here, with the Java location, where the Rust port pins it (a test or comment),
and what a fix would look like once parity is established.

Rules:
- **Do not fix these in the port until parity is proven** on the fixture corpus.
  Fixing during porting makes porting bugs indistinguishable from intentional fixes.
- Every task that finds a new one **appends a row** here (the task reviewer
  checks for it).
- Status: `pinned` = reproduced and covered by a test/comment; `totalized` =
  Rust returns a value where Java crashes (documented divergence, not a bug
  fix); `candidate` = suggested improvement, not a Java bug.

## Process notes

- Reviews that extract the Java method bodies verbatim into a JDK-23 harness
  and diff against the Rust on random inputs have been the most effective
  verification (20k–525k comparisons per task). Prefer that over hand-tracing
  for any algorithm over ~100 lines.
- Every deliberate divergence must be greppable: `// not ported:` for skipped
  members, `// totalized:` for crash-to-value changes, `// Java bug:` for
  reproduced defects.
- The differential harness lives in `scripts/differential/`. Every driver is a genuine
  Java-vs-Rust pair. `p2t3` is the fixed `ShapeTree`/`MinAreaTree` script that
  `crates/fr-board/tests/min_area_tree.rs` was written from; `p2t3r` is its randomised
  sibling, which also drives `insert_tiles`, `remove_opt` with `null` holes and in-place
  leaf re-keying.
- The `candidate` table doubles as the **obligation register**: rows whose text
  opens with a bolded "(Plan N obligation)" are not improvement ideas but work
  a later plan *must* do (pass-level recovery, MCP concurrency, legacy-CLI value
  normalisation). Each such row names the file that carries the same note in a
  code comment, so `grep -rn "obligation:"` finds them from the source side.
- Java's per-flag command-line value normalisation is tabulated separately in
  `docs/cli-legacy-flags.md`; `crates/freerouting/src/legacy.rs` forwards raw
  values and points at that file.
- **`tools/freerouting-2.3.0.jar` and the clone's HEAD differ in more than plan
  ruling 1's fifteen `Keyword` names.** Found in Plan 3 Task 9 while diffing the
  whole 104-file DSN fixture corpus: `DsnFile.readStringScope` gained a resync
  loop between the two. 2.3.0 does `yybegin(NAME); nextString(); nextToken(); if
  (!= CLOSED_BRACKET) warn;` and returns straight away, leaving the scanner
  wherever the stray token left it; HEAD drops the `yybegin` and adds `while
  (nextToken != null && nextToken != CLOSED_BRACKET) nextToken = nextToken();`,
  which resynchronises to the closing bracket. The port follows HEAD, per the
  plan's "Java source authority is the clone's HEAD" constraint. Exactly one
  corpus fixture is affected — `Issue229-display-8-digit-hc595.dsn`, whose
  `(PN "DISPLAY 7-SEG 0.5"")` has an unbalanced string quote. There, 2.3.0
  desynchronises and silently drops everything after the `structure` scope
  (`Success`, 1 item, 0 components, 0 nets), while HEAD — and this port — read
  on and produce 22 components and 30 nets. Verified against both jars with a
  reflective probe. **Task 15's corpus-wide differential runs against 2.3.0 and
  will see this fixture disagree; that disagreement is expected, not a port
  bug.** Minimal repro: a `(place … (PN "A 0.5""))` scope in any otherwise valid
  DSN.
