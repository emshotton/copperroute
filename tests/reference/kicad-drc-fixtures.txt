# kicad-cli DRC oracle fixtures for scripts/gen-kicad-drc-reference.sh and
# crates/copper-drc/tests/kicad_oracle.rs. A `corpus:` prefix is relative to tests/corpus,
# anything else to the repository root.
#
#   stem|dsn|ses|kicad_pcb|kicad_pro|ignore_types
#
# ignore_types lists KiCad violation types whose counts are not compared for that stem.
#
# kicad-issue191-z80:
#   - hole_clearance, drill_out_of_range: through-hole pad drills are estimated from padstack
#     geometry (no drill size travels through the DSN/SES round trip), so counts involving pads
#     can differ from kicad-cli's, which reads the real drill from the .kicad_pcb.
#   - unconnected_items: 5 single-pad `Net-(U33-PadN)` nets are named in the DSN/SES but absent
#     from the reference .kicad_pcb's net table, so `ses_to_board.py` logs them "net not found"
#     and never routes them there; kicad-cli reports the resulting 5 unconnected pads while the
#     port's own net table (built from the DSN, where the names do resolve) completes them.
# kicad-issue283-preamp: unconnected_items — freerouting's unconnected-items algorithm (ported
#   verbatim from the JVM's DesignRulesChecker, quirk #144) reports at most one missing-connection
#   pair per net regardless of how many disjoint copper islands that net has, where kicad-cli
#   reports one entry per missing link. GND and +5V on this board (the fixture Issue283 is titled
#   after: traces routed under pads without actually joining them) split into far more than two
#   islands each, so the two engines' counts diverge structurally, not from a checker bug.
