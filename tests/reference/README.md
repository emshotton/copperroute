# Java reference outputs

Generated by `scripts/gen-reference.sh` from the pinned freerouting 2.3.0 jar
(the parity baseline per the Java repo's AGENTS.md). For each stem in
`fixtures.txt` the script produces:

- `<stem>/roundtrip.dsn` — Java: read DSN, write DSN unchanged
  (`-do <stem>.dsn --router.enabled=false`)
- `<stem>/unrouted.ses` — Java: read DSN, write SES without routing
  (`-do <stem>.ses --router.enabled=false`)
- `<stem>/java.log`     — stderr/stdout of the Java run, for debugging

Routing is suppressed with the generic settings override `--router.enabled=false`
(`GlobalSettings.java:538-559`; `CliSettings.java:51,79-82` honours it explicitly
and then skips the implicit "`-de` plus `-do` means route" force-on).

**Not `-mp 0`.** In Java `maxPasses == 0` means *unlimited*, not "no passes":
`GlobalSettings.java:675-686` deliberately allows 0, and `RouterSettings.validate()`
(`RouterSettings.java:933-941`) rewrites it to `Integer.MAX_VALUE` with the comment
"0 means no limit". An earlier version of the generator used `-mp 0` and would have
produced *fully routed* references.

**Re-validate on the first JDK 25 run.** The `--router.enabled=false` path has not
yet been exercised against the 2.3.0 jar in this workspace. The first time
`scripts/gen-reference.sh` runs, open each `<stem>/unrouted.ses` and confirm its
`(routes …)` section contains only the wiring already present in the input DSN and
no newly routed traces. If it contains new traces, the override is not taking
effect and the references are not a valid parity baseline.

Reference files are committed. `_scratch/` holds the Rust side of a failing
comparison and is gitignored.

Requirements: Java 25 (`brew install openjdk@25` on macOS), network access on
first run to download the jar into `tools/`.
