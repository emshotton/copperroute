# The freeze

This directory is the historical baseline the port was proven byte-identical to at `c467758`,
generated by the clone's HEAD jar. It is **never again an assertion** — no test and no script reads
it (BL8 as amended by ruling BP1); the numbers derived from it live in `benchmark/baselines/`. It
exists so that a future reader can answer "what did the jar do here?" after the differential
drivers are gone.

## What is in it

```
tests/reference-frozen/java-head-2026-09/     212 files, 38 directories, 4 286 257 bytes
```

`rsync -a --exclude='_scratch/' tests/reference/ tests/reference-frozen/java-head-2026-09/`, taken
at Plan 9 Task 1 on top of `04a9312`, which is the last commit at which the port and the jar agree
byte-for-byte. A **sibling** of `tests/reference/`, never a child (ruling BP1): a recursive copy of
a directory into itself is not expressible on either BSD or GNU `rsync`, and a child would be swept
up by every glob that walks the live tree.

Verified before anything else happened, and the verification is the point of the exercise rather
than a formality:

* `diff -r -x _scratch tests/reference tests/reference-frozen/java-head-2026-09` — **empty**;
* a per-file `shasum -a 256` manifest of both sides — **identical, 212 of 212 files**;
* file, directory and byte counts equal on both sides.

The single exclusion is `tests/reference/_scratch/` (21 files), which `.gitignore:3` already
excludes from the repository: it is the generators' and the DRC parity tests' working space
(`drc.actual.json`, `drc.expected.json`, `roundtrip.dsn`), not reference data, and freezing one
machine's leftover temporary files as a historical baseline would misdescribe what this directory
is. Every **tracked** file under `tests/reference/` — all 212 of them, with no untracked extras — is
here.

Each stem's own `meta.txt` / `batch.meta.txt` / `drc.meta.txt` carries the full argv and the jar's
size and mtime; that is the provenance, and it travelled into the freeze with everything else.

## Read once, and then never again

The one and only read of this tree was Task 1's derivation of the jar quality column, which
happened **before** the `chmod -R a-w` and wrote its output **outside** the tree, to

```
benchmark/baselines/quality-baseline-java-head.tsv
```

where `scripts/quality-ab.sh` renders it into every A/B row's `jar_*` columns as context and never
as a gate. That file's own header records how each column was derived. The derivation script was
deliberately **not** committed: a committed script that reads this directory is exactly the reader
BL8 forbids, and

```
grep -rn "reference-frozen" crates/ scripts/ benchmark/
```

must return nothing but prose for the whole of Plan 9. `tests/reference/README.md` says the same
thing from the other end.

## Why it is read-only

`chmod -R a-w tests/reference-frozen/java-head-2026-09/`, applied after the tsv was written. From
Plan 9 Task 1 onwards `tests/reference/` is regenerated **from the port** and byte parity with the
jar may break wherever a fix lands. This directory is the only surviving record of where the jar
stood, it cannot be recut once the differential drivers are retired, and a write into it would
destroy something nothing can restore. To read a file here, just read it. To change one: don't.

Git records only the executable bit, so a **fresh checkout gets ordinary `0644` files** and the
mode does not travel. That is not a hole in the argument, because the protection that matters is
the one that survives: nothing reads this tree, so nothing has a reason to write it, and the
`grep` above is what enforces that. `chmod -R a-w` protects the working tree it was applied to —
this one, where the rest of Plan 9 is about to be implemented — and this paragraph is the
instruction for every other checkout.
